= Production Architecture
:navtitle: Production Architecture

Understand how the workshop environment maps to a production Maximo on OpenShift deployment.

== Workshop vs. Production

This workshop demonstrates concepts at conference scale. A production deployment differs in several key areas:

[cols="1,2,2"]
|===
| Area | Workshop | Production

| Cluster sizing
| Minimal (workshop workload)
| Sized for peak asset management load

| High availability
| Single availability zone
| Multi-AZ with disaster recovery

| Database
| Db2 inside cluster
| Managed database service or dedicated HA Db2

| Identity
| htpasswd + Keycloak demo
| Enterprise IdP (SAML/OIDC) with MFA

| Logging retention
| Hours (event duration)
| 30-90+ days per compliance policy

| Storage
| Default StorageClass
| Production-grade storage with backup

| Updates
| Pinned for stability
| Scheduled maintenance windows with rollback

| ACM
| Fleet demonstration
| Production governance and compliance
|===

== Production Sizing Guidelines

The following are reference guidelines. Actual sizing depends on your workload.

=== OpenShift Cluster

* *Workers*: minimum 3 (HA), recommended 5+ for MAS
* *CPU per worker*: 16+ vCPUs
* *Memory per worker*: 64+ GiB
* *Storage*: 500+ GiB persistent storage per worker

=== Maximo Application Suite

* *MAS Core*: 8 vCPU, 32 GiB RAM minimum
* *Maximo Manage*: 16 vCPU, 64 GiB RAM minimum (depends on modules)
* *Database*: separate compute or managed service
* *Object Storage*: S3 or compatible for attachments and logs

== Key Takeaways

. MAS on OpenShift provides a consistent platform for enterprise asset management
. RHACM enables fleet-wide governance and visibility
. OpenShift Logging with Loki provides scalable observability
. Identity integration connects MAS to enterprise directories
. Automation (Ansible, operators) ensures consistent, repeatable deployments
