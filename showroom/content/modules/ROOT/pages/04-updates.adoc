= Updates and Why You Should Care
:navtitle: Updates and Why You Should Care
:duration: 20 minutes

Understand how MAS and OpenShift updates are managed in an enterprise environment.

== Introduction

Keeping Maximo Application Suite and OpenShift current requires coordinating:

* OpenShift platform updates
* Operator Lifecycle Manager (OLM) updates
* MAS operator channel updates
* Maximo Manage application updates

In this section, you will explore the update mechanisms through the OpenShift Console and understand the operational workflow.

== Exercise: Check Current Versions

. In the OpenShift Console, navigate to *Administration* > *Cluster Settings*.
. On the *Details* tab, locate the *Current version* field. This shows your OpenShift platform version (e.g., `{ocp_version}`).
. Note the *Channel* field -- this determines which update stream your cluster follows.
. Now navigate to *Operators* > *Installed Operators*.
. Use the *Project* dropdown to select `mas-inst1-core`.
. Observe the list of IBM MAS operators. Note the *Version* column -- this shows the installed version of each operator.
. Click on any IBM operator (e.g., *IBM Maximo Application Suite*) to open its details.
. Select the *Subscription* tab. Here you can see:
+
* *Channel* -- the version stream the operator tracks
* *Source* -- the catalog source providing operator metadata
* *Approval* -- whether updates are applied automatically or require manual approval

== Exercise: Explore Update Channels

. While viewing an operator's *Subscription* tab, click the *Channel* value to see available channels.
. Each channel represents a different version stream. For MAS, channels typically follow the `9.x` pattern.
. Click *Cancel* to return without making changes.
. Now navigate to *Operators* > *Installed Operators* in the `mas-inst1-core` project.
. Click on any operator, then select the *InstallPlan* tab.
. Review the install plans -- each one records what an operator update will install or has installed.

== Exercise: Understand the Update Process

. Navigate to *Administration* > *Cluster Settings*.
. Select the *ClusterVersion* details tab.
. Review the *Update History* section at the bottom. This shows all OpenShift version transitions your cluster has gone through, with timestamps and status.
. Note the *Conditions* section. It shows whether the cluster is currently updating, available for updates, or has any degraded components.
. Navigate to the *Cluster Operators* tab. This lists all cluster operators and their current status. All should show *Available = True*, *Progressing = False*, *Degraded = False* for a healthy cluster.

== Key Concepts

[cols="1,2"]
|===
| Concept | Description

| Operator Channel
| Determines which version stream an operator tracks (e.g., `9.x`)

| InstallPlan
| Records what an operator update will install

| ClusterVersion
| Tracks OpenShift platform version and update availability

| Catalog Source
| Provides operator metadata to OLM (e.g., `v9-260625-amd64`)
|===

== Production Considerations

* Pin operator channels to specific major.minor versions for stability
* Use the IBM MAS catalog source version tag, not `latest`
* Schedule OpenShift updates during maintenance windows
* Test MAS compatibility with new OpenShift versions before upgrading
* Maintain an update runbook with rollback procedures

WARNING: Do not update OpenShift beyond the MAS-supported version range ({ocp_version} is the current target).
