= Observability and Logging
:navtitle: Observability and Logging
:duration: 45 minutes

Install and configure the OpenShift Logging stack with Loki to observe your Maximo environment.

== Introduction

In this exercise you will install and configure a complete cluster logging stack from scratch. By the end, you will have:

* Installed three operators (Logging, Loki, Cluster Observability)
* Created an S3-backed LokiStack for log storage
* Configured log collection and forwarding
* Enabled console-integrated log viewing
* Generated test logs and queried them with LogQL

== Architecture Overview

You will build the following stack:

[cols="1,2"]
|===
| Component | Purpose

| OpenShift Logging Operator
| Manages the log collection pipeline (Vector-based collector)

| Loki Operator
| Manages the LokiStack deployment for log storage and indexing

| Cluster Observability Operator (COO)
| Provides UIPlugin for integrated log viewing in the OpenShift Console

| LokiStack
| Stores and indexes logs with S3 backend

| ClusterLogForwarder
| Routes application, infrastructure, and audit logs to LokiStack

| AWS S3
| Object storage for Loki log data (pre-created for you)
|===

== Step 1: Install the OpenShift Logging Operator

The Logging Operator requires its own namespace and OperatorGroup.

. Create the `openshift-logging` namespace:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: v1
kind: Namespace
metadata:
  name: openshift-logging
  labels:
    openshift.io/cluster-monitoring: "true"
EOF
----
+
. Create the OperatorGroup:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: openshift-logging
  namespace: openshift-logging
spec:
  targetNamespaces:
    - openshift-logging
EOF
----
+
. Install the Logging Operator via Subscription:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: cluster-logging
  namespace: openshift-logging
spec:
  channel: stable-6.6
  name: cluster-logging
  source: redhat-operators
  sourceNamespace: openshift-marketplace
  installPlanApproval: Automatic
EOF
----
+
. Wait for the operator to install (this may take 1-2 minutes):
+
[source,role="execute"]
----
oc get csv -n openshift-logging -w
----
+
Wait until the `PHASE` column shows `Succeeded`, then press `Ctrl+C` to stop watching.

== Step 2: Install the Loki Operator

The Loki Operator installs into the same `openshift-logging` namespace. It does not need a separate OperatorGroup.

. Install the Loki Operator:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: loki-operator
  namespace: openshift-logging
spec:
  channel: stable-6.6
  name: loki-operator
  source: redhat-operators
  sourceNamespace: openshift-marketplace
  installPlanApproval: Automatic
EOF
----
+
. Verify both operators are installed:
+
[source,role="execute"]
----
oc get csv -n openshift-logging --no-headers
----
+
.Expected output (versions may vary)
[source,text]
----
cluster-logging.v6.6.x   Red Hat OpenShift Logging   Succeeded
loki-operator.v6.6.x     Loki Operator               Succeeded
----

== Step 3: Install the Cluster Observability Operator

The Cluster Observability Operator (COO) enables integrated log viewing directly in the OpenShift Console.

. Install COO:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: cluster-observability-operator
  namespace: openshift-operators
spec:
  channel: stable
  name: cluster-observability-operator
  source: redhat-operators
  sourceNamespace: openshift-marketplace
  installPlanApproval: Automatic
EOF
----
+
. Wait for COO to install:
+
[source,role="execute"]
----
oc get csv -n openshift-operators --no-headers | grep observability
----
+
Wait until the phase shows `Succeeded`.

== Step 4: Create the S3 Storage Secret

LokiStack needs S3 credentials to store log data. Your S3 bucket has been pre-created. Use the credentials from the information panel on this page.

. Create the storage secret:
+
[source,role="execute"]
----
oc create secret generic logging-loki-s3 \
  -n openshift-logging \
  --from-literal=bucketnames={s3_bucket_name} \
  --from-literal=region={s3_region} \
  --from-literal=access_key_id={s3_access_key_id} \
  --from-literal=access_key_secret={s3_secret_access_key} \
  --from-literal=endpoint=https://s3.{s3_region}.amazonaws.com
----
+
. Verify the secret was created:
+
[source,role="execute"]
----
oc get secret logging-loki-s3 -n openshift-logging
----

== Step 5: Deploy LokiStack

. Create the LokiStack custom resource:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: loki.grafana.com/v1
kind: LokiStack
metadata:
  name: logging-loki
  namespace: openshift-logging
spec:
  size: 1x.extra-small
  storage:
    schemas:
      - version: v13
        effectiveDate: "2024-10-01"
    secret:
      name: logging-loki-s3
      type: s3
  storageClassName: gp3-csi
  tenants:
    mode: openshift-logging
  limits:
    global:
      retention:
        days: 3
EOF
----
+
. Wait for LokiStack to become ready (this may take 3-5 minutes):
+
[source,role="execute"]
----
oc get lokistack logging-loki -n openshift-logging -w
----
+
Wait for `READY` to show `True`, then press `Ctrl+C`.
+
. Verify all LokiStack pods are running:
+
[source,role="execute"]
----
oc get pods -n openshift-logging -l app.kubernetes.io/instance=logging-loki --no-headers
----

== Step 6: Configure Log Collection

The ClusterLogForwarder tells the Logging Operator what logs to collect and where to send them.

. Create the collector ServiceAccount and grant required permissions:
+
[source,role="execute"]
----
oc create serviceaccount collector -n openshift-logging
oc adm policy add-cluster-role-to-user collect-application-logs -z collector -n openshift-logging
oc adm policy add-cluster-role-to-user collect-infrastructure-logs -z collector -n openshift-logging
oc adm policy add-cluster-role-to-user collect-audit-logs -z collector -n openshift-logging
----
+
. Create the ClusterLogForwarder:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: observability.openshift.io/v1
kind: ClusterLogForwarder
metadata:
  name: collector
  namespace: openshift-logging
spec:
  serviceAccount:
    name: collector
  outputs:
    - name: default-lokistack
      type: lokiStack
      lokiStack:
        target:
          name: logging-loki
          namespace: openshift-logging
        authentication:
          token:
            from: serviceAccount
  pipelines:
    - name: application-logs
      inputRefs:
        - application
      outputRefs:
        - default-lokistack
    - name: infrastructure-logs
      inputRefs:
        - infrastructure
      outputRefs:
        - default-lokistack
    - name: audit-logs
      inputRefs:
        - audit
      outputRefs:
        - default-lokistack
EOF
----
+
. Verify the collector pods are running:
+
[source,role="execute"]
----
oc get pods -n openshift-logging -l app.kubernetes.io/component=collector --no-headers
----
+
You should see collector pods running on each node.

== Step 7: Enable Console Log Viewing

The Cluster Observability Operator provides a UIPlugin that adds a *Logs* tab to the OpenShift Console.

. Create the UIPlugin:
+
[source,role="execute"]
----
cat <<EOF | oc apply -f -
apiVersion: observability.openshift.io/v1alpha1
kind: UIPlugin
metadata:
  name: logging
spec:
  type: Logging
  logging:
    lokiStack:
      name: logging-loki
    logsLimit: 50
EOF
----
+
. Verify the plugin is available:
+
[source,role="execute"]
----
oc get uiplugin logging
----

== Step 8: Generate and Query Logs

. Create a log-generating workload in your namespace:
+
[source,role="execute",subs="+attributes"]
----
oc run log-test-{seat_number} \
  --image=registry.access.redhat.com/ubi9/ubi-minimal:9.4 \
  -n student-{seat_number} \
  --restart=Never \
  -- /bin/bash -c 'for i in $(seq 1 10); do echo "{\"msg\":\"MAS World log test\",\"seat\":\"{seat_number}\",\"iteration\":$i,\"timestamp\":\"$(date -u +%Y-%m-%dT%H:%M:%SZ)\"}"; sleep 2; done'
----
+
. Wait for the pod to complete:
+
[source,role="execute",subs="+attributes"]
----
oc wait pod/log-test-{seat_number} -n student-{seat_number} --for=condition=Ready --timeout=30s 2>/dev/null; sleep 25
----
+
. Verify the logs were generated:
+
[source,role="execute",subs="+attributes"]
----
oc logs log-test-{seat_number} -n student-{seat_number}
----

== Step 9: Query Logs with LogQL

You can query logs through the OpenShift Console (if the UIPlugin loaded) or directly via the Loki API.

. Query your test logs from the terminal:
+
[source,role="execute"]
----
oc logs -n openshift-logging -l app.kubernetes.io/component=distributor --tail=5
----
+
. Open the *OpenShift Console* tab on the right and navigate to *Observe > Logs* (if the COO UIPlugin is active).
. Enter this LogQL query:
+
[source,text,subs="+attributes"]
----
\{kubernetes_namespace_name="student-{seat_number}"} |= "MAS World log test"
----
+
. Try filtering by seat number:
+
[source,text,subs="+attributes"]
----
\{kubernetes_namespace_name="student-{seat_number}"} | json | seat="{seat_number}"
----

== Step 10: Clean Up

. Delete your test pod:
+
[source,role="execute",subs="+attributes"]
----
oc delete pod log-test-{seat_number} -n student-{seat_number}
----
+
. Verify the logs *persist* in Loki after the pod is deleted (query again — the historical logs remain).

== Production Considerations

[cols="1,1,2"]
|===
| Aspect | Workshop | Production

| Loki size
| `1x.extra-small`
| `1x.medium` or larger

| S3 storage
| Single bucket per cluster
| Dedicated bucket with lifecycle policies

| Retention
| 3 days (event duration)
| 30-90 days or longer per compliance

| SIEM integration
| Not configured
| Forward to Splunk, CloudWatch, or similar

| Log types
| Application + Infrastructure + Audit
| Same, plus custom forwarding rules

| Console integration
| COO UIPlugin (basic)
| Grafana dashboards + alerting rules
|===
