= Updates
:navtitle: Updates
:duration: 20 minutes

Understand how MAS and OpenShift updates are managed in an enterprise environment.

== Introduction

Keeping Maximo Application Suite and OpenShift current requires coordinating:

* OpenShift platform updates
* Operator Lifecycle Manager (OLM) updates
* MAS operator channel updates
* Maximo Manage application updates
* Database schema migrations

In this section, you will explore the update mechanisms and understand the operational workflow.

== Exercise: Check Current Versions

. Check your OpenShift version:
+
[source,role="execute"]
----
oc get clusterversion version -o jsonpath='{.status.desired.version}'
----
+
. Check the MAS operator version:
+
[source,role="execute"]
----
oc get csv -n mas-inst1-core -o jsonpath='{range .items[*]}{.metadata.name}{"\n"}{end}'
----
+
. Check the operator subscriptions:
+
[source,role="execute"]
----
oc get subscription -n mas-inst1-core -o custom-columns=NAME:.metadata.name,CHANNEL:.spec.channel,SOURCE:.spec.source
----

== Exercise: Explore Update Channels

. View available channels for the MAS operator:
+
[source,role="execute"]
----
oc get packagemanifest ibm-mas -n openshift-marketplace -o jsonpath='{range .status.channels[*]}{.name}{"\n"}{end}'
----
+
. View the current install plan:
+
[source,role="execute"]
----
oc get installplan -n mas-inst1-core --no-headers
----

== Exercise: Understand the Update Process

. Check if there are pending updates for the cluster:
+
[source,role="execute"]
----
oc get clusterversion version -o jsonpath='{.status.availableUpdates[*].version}'
----
+
. View the update history:
+
[source,role="execute"]
----
oc get clusterversion version -o jsonpath='{range .status.history[*]}{.version}{" - "}{.state}{"\n"}{end}'
----

== Key Concepts

[cols="1,2"]
|===
| Concept | Description

| Operator Channel
| Determines which version stream an operator tracks (e.g., `9.x`)

| InstallPlan
| Records what an operator update will install

| ClusterVersion
| Tracks OpenShift platform version and update availability

| Catalog Source
| Provides operator metadata to OLM (e.g., `v9-260625-amd64`)
|===

== Production Considerations

* Pin operator channels to specific major.minor versions for stability
* Use the IBM MAS catalog source version tag, not `latest`
* Schedule OpenShift updates during maintenance windows
* Test MAS compatibility with new OpenShift versions before upgrading
* Maintain an update runbook with rollback procedures

WARNING: Do not update OpenShift beyond the MAS-supported version range ({ocp_version} is the current target).
